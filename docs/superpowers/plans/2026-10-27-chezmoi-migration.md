# Stow → chezmoi Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace GNU Stow with chezmoi for managing `$HOME` dotfiles on Debian/WSL, with a sync script that moves edits in both directions (home → repo and repo → home), and migrate existing stow machines.

**Architecture:** The chezmoi source state lives in `home/` inside `~/.dotfiles` (selected by a `.chezmoiroot` file), so the setup guides stay at the repo root. chezmoi runs in its default copy mode for every file (no symlink mode). A new `sync.sh` re-adds files edited in `$HOME` into the repo (when the repo side hasn't changed since the last apply), pulls, then applies. `install.sh` and `update.sh` call it in place of `stow`. Templates are used only for files no other tool writes to. The per-machine git email lives in a templated `~/.gitconfig.local` that `~/.gitconfig` includes, so `~/.gitconfig` stays re-addable.

**Tech Stack:** chezmoi 2.x, Bash, git 2.47

**Spec:** No separate spec doc. The decisions below came from the 2026-10-27 conversation and are copied into Global Constraints.

## Global Constraints

- Copy mode only: never set `mode = "symlink"` in chezmoi config.
- Templates (`*.tmpl`) only for files that no other tool rewrites. `~/.gitconfig` is **not** a template; the email goes in `home/dot_gitconfig.local.tmpl`.
- Repo stays at `~/.dotfiles`; chezmoi source root is `~/.dotfiles/home` via `.chezmoiroot` containing `home`.
- Scripts never commit or push; they finish by telling the user to review `git diff` (same as today).
- Every script keeps `--dry-run` support, and dry-run changes nothing in `$HOME` or the repo.
- New shell scripts: `#!/usr/bin/env bash`, `set -euo pipefail`, 2-space indent (AGENTS.md). Edits inside `install.sh`/`update.sh` keep those files' existing 4-space indent and `print_*`/`run` helpers.
- Markdown: no hard wrapping.
- Windows scripts, `.chezmoiexternal` (e.g. superpowers clone), and password-manager secrets are **out of scope**; they belong to a follow-up plan.

## Review Focus

- **Stow machine pulls the restructure before migrating:** its `$HOME` symlinks now point at deleted paths. Expected: `./install.sh` removes every symlink into `~/.dotfiles` (dangling or not) and applies cleanly. Owned by Task 3, verified in Task 4.
- **Claude Code rewrites `~/.claude/settings.json` several times between commits:** each edit should be re-added on the next sync, not reported as a conflict. Owned by Task 2, `test_repeated_local_edits_between_commits_are_readded`.
- **Overlapping edits to the same file on two machines:** sync must stop with a git conflict and must not apply a half-merged source. Owned by Task 2, `test_overlapping_edits_stop_with_git_conflict`.
- **Local edit to a templated file (`~/.gitconfig.local`):** `re-add` can't handle templates, so sync must report it with a `chezmoi merge` hint and leave both sides untouched. Owned by Task 2, `test_template_edit_is_reported_not_readded`.
- **Dry-run on a real machine:** must not pull, re-add or apply. Owned by Task 2, `test_dry_run_changes_nothing`.

### Task 2: `sync.sh` — two-way sync between `$HOME` and the repo

**Files:**
- Create: `sync.sh` (executable), `tests/sync.test.sh` (executable)

**Interfaces:**
- Consumes: chezmoi config and `home/` from Task 1.
- Produces: `sync.sh [--dry-run] [--no-pull]`. It reads `DOTFILES_REPO` (default `$HOME/.dotfiles`). Exit 0 on success, including when conflicts were reported. Exit 1 when `git pull` or the stash pop leaves a git conflict (nothing is applied in that case).

**Algorithm (the part the tests don't fully determine):**

1. **Classify local edits.** Parse `chezmoi status`: column 1 is the char at index 0; the path starts at index 3 and is relative to `$HOME`. For each line with column 1 = `M`:
   - If `chezmoi source-path <target>` ends in `.tmpl` → conflict, kind `template`.
   - Else, if the source has changed since the last apply → conflict, kind `both`. "Changed" means sha256 of `chezmoi cat <target>` ≠ `contentsSHA256` in `chezmoi state get --bucket=entryState --key=<abs target>`. Extract it with `sed`; no `jq` dependency.
   - Else → re-add: `chezmoi re-add <target>` then `chezmoi apply --force <target>`. The forced apply writes identical content; it's there to record the new entry state, so the next sync sees no column-1 change.

   Column 1 = `D` → conflict, kind `deleted`.
2. **Pull** (skipped with `--no-pull`). If the repo is dirty: `git stash push -m sync.sh`. Then `git pull --rebase`, then `git stash pop` if a stash was made. If either step fails, or `git diff --name-only --diff-filter=U` is non-empty: print the unmerged files with `print_warn` and exit 1.
3. **Apply.** With no conflicts, run `chezmoi apply`. Otherwise run `chezmoi apply` with the absolute paths from `chezmoi managed --include=files,symlinks --path-style=absolute` minus the conflicted targets. This keeps chezmoi from prompting.
4. **Report.** List re-added files ("review with `git diff`, then commit and push"). List conflicts with a hint per kind: `template`/`both` → `chezmoi merge ~/<path>`; `deleted` → `chezmoi forget ~/<path>` to stop managing, or `chezmoi apply ~/<path>` to restore.

`--dry-run` prints the classification with `print_dry` lines ("Re-add …", "git pull --rebase", "chezmoi apply") and mutates nothing. Copy the colour/`print_*` helpers from `update.sh`.

**Test harness (`tests/sync.test.sh`):** each test calls `setup`, which:
- creates `TMP=$(mktemp -d)` and exports `HOME=$TMP/home` and the `GIT_AUTHOR_*`/`GIT_COMMITTER_*` env vars;
- creates a bare remote `$TMP/remote.git` seeded with `.chezmoiroot` (`home`), a minimal `home/.chezmoi.toml.tmpl` (as in Task 1), and `home/dot_plainrc` (`one`), `home/dot_otherrc` (`a`) and `home/dot_tmplrc.tmpl` (`email={{ .email }}`);
- clones the remote to `$HOME/.dotfiles` and to `$TMP/other` (the "other machine");
- runs `chezmoi init --source $HOME/.dotfiles --promptString email=t@example.com` and `chezmoi apply`.

`upstream "<file>" "<content>"` commits and pushes from `$TMP/other`. Tests run `$REPO_ROOT/sync.sh`. The script prints `PASS <name>`/`FAIL <name>: <reason>` per test and exits non-zero if any fail.
